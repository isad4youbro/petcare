# HTTP API PetCare

Интерактивная [Swagger-документация](http://127.0.0.1:8000/swagger) и [схема OpenAPI JSON](http://127.0.0.1:8000/openapi.json) доступны публично. RFC проекта — [RFC-001.md](RFC-001.md).

Локальная база URL: `http://127.0.0.1:8000/api`. JSON в UTF-8. POST требует `Content-Type: application/json` и объект JSON до 3 000 000 байт. После сохранения интерфейс перечитывает `/state`.

## Авторизация

Постоянный аккаунт регистрируется через POST /api/register и входит через POST /api/login с username/password. Логин нормализуется в нижний регистр, уникален, 3–32 символа [a-z][a-z0-9_]{2,31}; пароль 10–128 символов. Сервер хранит PBKDF2-SHA256 с солью, 310000 итераций. Конфликт имени — 409, неверные данные входа — 401, rate limit — 429. Успех устанавливает `petcare_session`: HttpOnly, SameSite=Strict, Path=/, срок 30 дней. Для публичного HTTPS необходимо `PETCARE_SECURE_COOKIES=1`. В базе хранится SHA-256 токена сессии.

Пробный просмотр получает `demoToken` из `/demo` и сохраняет его в `sessionStorage`. Для защищённых запросов, включая экспорт календаря, передаётся `X-PetCare-Demo`. Токен действует 24 часа; cookie для демо не устанавливается. Заголовок имеет приоритет над cookie: просроченное или неверное демо получает 401 без перехода в постоянный аккаунт. Обычная cookie не авторизует демо-профиль, заголовок демо не авторизует постоянный профиль.

Сервер сверяет `Origin` с `Host` и отклоняет `Sec-Fetch-Site: cross-site`. Frontend и API должны иметь один origin.

## Маршруты

Пути указаны относительно `/api`.

| Метод | Путь | Доступ и результат |
| --- | --- | --- |
| GET | `/health` | Публичный healthcheck с проверкой SQLite: `{ok:true,service:"PetCare"}` |
| POST | `/auth/request-code` | Публичный; `email,mode,name?` → `challengeId,expiresIn,resendAfter` |
| POST | `/auth/verify-code` | Публичный; `challengeId,code` → `{ok:true}` и cookie |
| POST | `/register`, `/login` | Постоянный аккаунт: {username,password}; успех {ok:true} и cookie |
| POST | `/demo` | Публичный; создаёт независимую копию примеров → `{ok:true,demoToken}` |
| POST | `/logout` | Завершает постоянную сессию либо удаляет текущий демо-профиль с его данными |
| POST | `/onboard` | Сохраняет прохождение знакомства |
| GET | `/state` | `user,pets[],telegram,ai,today` текущего владельца |
| GET | `/food/suggest?q=...` | До 8 подсказок марок корма по запросу из каталога и личных записей владельца |
| POST | `/pets/save` | Создаёт или обновляет собственного питомца → `{id}` |
| POST | `/pets/delete` | `petId`; удаляет питомца и его записи |
| POST | `/records/save` | `petId,kind,id?` и поля записи → `{id}` |
| POST | `/records/delete` | `petId,id`; удаляет свою запись и согласует связанные невыполненные события |
| POST | `/search` | `petId,question` → `answer,mode,sources[]` |
| GET | `/calendar.ics` | Невыполненные события владельца, `text/calendar; charset=utf-8`; необязательный `petId` ограничивает выгрузку своим питомцем (чужой или неизвестный ID → 404) |
| POST | `/telegram/link` | Постоянный аккаунт или активное демо; одноразовый `url` для Start, 10 минут |
| POST | `/telegram/unlink` | Постоянный аккаунт или активное демо; удаляет его связь с Telegram |
| POST | `/telegram/test` | Постоянный аккаунт или активное демо; тест подключённому владельцу |

Кроме `/health`, маршрутов входа и `/demo`, нужна авторизация. Для POST без полезных полей отправляется `{}`. Активное демо допускает Telegram; ссылка одноразовая и действует 10 минут. Не настроенный или недоступный Telegram возвращает 503, а не фиктивную успешную привязку.

### Пример постоянного входа

POST /api/register или POST /api/login, Content-Type: application/json:

{"username":"petcare_owner","password":"replace-with-private-password"}

После успеха GET /api/state возвращает пользователя и его питомцев. /api/pets, записи, назначения и метки сохраняются на backend и проверяют владельца. При успешном входе frontend удаляет токен текущего демо, чтобы запросы перешли на постоянную сессию. Пароли не передавать боту.

### Совместимость: старый почтовый код (не используется текущей формой)

Регистрация:

```json
{"email":"owner@example.org","mode":"register","name":"Алексей"}
```

`mode` — `register/login`; имя обязательно для регистрации. Email нормализуется в нижний регистр. Шестизначный код отправляется только SMTP-сервисом: не возвращается в JSON и не выводится в логи. В базе — PBKDF2-HMAC-SHA256 с индивидуальной солью, срок 600 секунд, до 5 неверных попыток. Код одноразовый; новый запрос заменяет прежний код этой почты. Повторная отправка — не ранее 60 секунд; лимит — 10 запросов с IP за 10 минут в памяти процесса.

Подтверждение:

```json
{"challengeId":"ID_ИЗ_ОТВЕТА_ЗАПРОСА","code":"123456"}
```

Для неизвестной почты в режиме `login` возвращается предложение зарегистрироваться. Регистрация существующей почты после подтверждения входит в её аккаунт. Текущая форма использует логин и пароль без SMTP; SMS нет. Без SMTP запрос получает 503; отказ транспорта — 502 с удалением неотправленного challenge. SMTP не настроен; реальная отправка письма не подтверждена.

### Пробный просмотр

`POST /demo` принимает `{}`. Лимит — 25 запросов с IP за минуту. Перед созданием удаляются демо-профили без действующей сессии и просроченные сессии. Выход удаляет профиль каскадно. Закрытие вкладки не гарантирует запрос удаления; серверная копия истекает через 24 часа и очищается при следующем создании демо. При 401 frontend сохраняет просроченный демо-токен до явного выхода или новой копии, чтобы следующие запросы не попали в постоянный аккаунт по cookie.

## Данные

### Питомец

Обязательны `name,species`; для обновления передаётся `id`. Необязательные: `breed,birthday,weight,photo,pixelPhoto,avatar`. Имя и название вида — до 100 символов. `species` — ID каталога либо произвольное название. Дата рождения `YYYY-MM-DD`, не в будущем; вес — число в кг больше 0 и меньше 2000 либо пустая строка.

`photo` — data URL JPEG/PNG/WebP, ориентировочно до 2 МБ бинарного изображения. `pixelPhoto` — data URL PNG с заголовком размера 32×32, до 20 000 символов. Пустая строка очищает изображение.

Активный конфиг — `avatar.sprite`:

| Поле | Ограничение |
| --- | --- |
| `engineVersion` | `1` |
| `species` | Один из 167 ID каталога |
| `parts` | Части и варианты, разрешённые для типа тела |
| `pattern` | Узор, разрешённый для типа тела |
| `colors` | `base,sec,pat,eye,ext,feet,acc`; значения из палитры, без `#` |
| `neck` | `none/collar/bell/bandana`; UI предлагает подходящие базовые варианты |
| `head` | `none/bow/flower/hat/glasses`; совместимость формата библиотеки |
| `paint` | Словарь разрешённых пиксельных ключей → цвет палитры, до 1100 элементов |
| `paintBase` | `constructor/white` |

Allowlist проверяется через `backend/avatar_catalog.json` и `avatar_config.py`. Имя берётся из данных питомца. Старые поля `avatar.shape,color,secondary,eyes,collar,pattern` сохранены для совместимости; frontend переводит их в новый рендерер. Старый цвет — `#RRGGBB`, узор — `plain/stripes/spots/patches`.

### Медицинская запись

`kind:"health",type,title,date,clinic?,doctor?,notes?,nextDate?`. Тип — `visit/vaccine/parasite/medicine/weight`. Дата записи не может быть будущей. `notes` — до 10 000 символов.

- Процедура: `repeatEvery` — целое 1…3650, `repeatUnit:days/months/years`, только для вакцинаций и обработок. Сервер рассчитывает `nextDate`. Конец месяца ограничивается последним существующим днём. Можно задать следующую дату явно, позже даты процедуры.
- Курс: `dose,courseStart,courseDays,courseEveryDays,courseTimes` для `medicine`. Длительность и периодичность — целые 1…365, до 8 времён в сутки, до 600 приёмов за курс. Например, `courseTimes:"08:00, 20:00"`. Конец включительный; сервер возвращает `courseEnd`. Без `courseDays` сохраняется текстовое назначение.
- Измерение: `measurement,value,unit`. Число положительное и конечное, допускает запятую. При заполнении части тройки нужны остальные поля. Старые текстовые измерения поддерживаются.

Пример:

```json
{"petId":"ID_ПИТОМЦА","kind":"health","type":"vaccine","title":"Вакцина по назначению","date":"2026-01-31","repeatEvery":1,"repeatUnit":"months","notes":"Интервал из назначения врача"}
```

Создаёт запись и связанное напоминание `2026-02-28 10:00`, канал `telegram`. Повторное сохранение с тем же `id` не создаёт дубль. Изменение назначения согласует невыполненные события; выполненные сохраняются. Удаление назначения удаляет его невыполненные события.

### Питание

`kind:"food",brand,flavor,amount,date,liked,tolerance,rating,reaction,notes?`.

- `brand,flavor,amount,date` обязательны; дата не в будущем, порция свободная, например `половина пакетика`.
- `liked:yes/no/unknown` и `tolerance:good/bad/unknown` независимы.
- `rating` — 0…5; `reaction:none/gi/allergy/other`, по умолчанию `none`.
- Реакция кроме `none` требует `tolerance:"bad"`. Переносимость — наблюдение владельца, не автоматическая медицинская оценка.

### Напоминание

`kind:"reminder",title,date,time,type,channel,notes?,done`.

- Дата `YYYY-MM-DD`, время `HH:MM`, часовой пояс Москва, UTC+3.
- Тип — `visit/vaccine/parasite/medicine/food/other`.
- Текущий UI создаёт `channel:"telegram"`. API сохраняет совместимость со `site/both`; Web Push выключен по умолчанию.
- `done` — отметка выполнения. `sourceId` для назначения создаётся сервером и сохраняется при редактировании; клиент не создаёт произвольную связь.

### Ответ поиска

```json
{"answer":"Текст по записям питомца","mode":"local","sources":[{"id":"ID_ЗАПИСИ","kind":"food","title":"Название","date":"2026-10-17"}]}
```

`mode`: `local/model/fallback`. Модель вызывается только при обеих настройках `OPENAI_API_KEY` и `OPENAI_MODEL`, разрешённых внешних запросах и успешном ответе сервиса. Иначе работает локальный поиск. Вопрос — до 1000 символов. Источники ограничены выбранным питомцем. API не назначает лечение.

## Публичные QR-метки и сообщения

- GET /api/tags/manage/PET_ID — настройки и последние события своей метки; требуется владелец.
- POST /api/tags/save — публикация выбранных полей своей метки с confirmPublish. Для активной карточки обязательны имя и телефон. Полный адрес требует отдельного shareFullAddress.
- GET /api/tags/public/TOKEN — публичная карточка без входа. Возвращает active/unactivated/disabled/unavailable; не раскрывает остальной дневник.
- POST /api/tags/public/TOKEN/scan — отдельное событие открытия; не означает, что питомец найден.
- POST /api/tags/public/TOKEN/report — ситуация with_me/seen/tag_only, place, comment, seenAt, необязательные finderName/finderPhone/photo. requestId обеспечивает защиту от повторного сохранения. Координаты location допустимы только при shareLocation:true.

Фото принимается как data URL JPEG/PNG/WebP. Frontend проверяет файл до 25 МБ, HEIC/HEIF преобразует в JPEG в браузере, ограничивает сторону 1600 px и итог до 2 600 000 символов data URL. Лимит JSON запроса остаётся 3 000 000 байт. Перед отправкой пользователь подтверждает предпросмотр. Успех означает запись в SQLite, а не доставку/прочтение Telegram. Отчёт виден владельцу через manage; планировщик пытается отправить текст в привязанный chat_id. Фото автоматически в Telegram не отправляется.

Публичные сообщения ограничены шестью в минуту с IP. Telegram link/test при недоступном Bot API возвращают ошибку, а не фиктивную привязку. Подробная схема полей и ответов — OpenAPI JSON.

## Необязательные маршруты Web Push

Исходники сохранены, канал выключен и скрыт из продукта. Отдельное включение — `PETCARE_ENABLE_WEB_PUSH=1` и зависимости.

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/push/config` | `configured,publicKey`; приватный ключ не возвращается |
| POST | `/push/subscribe` | `subscription:{endpoint,keys:{p256dh,auth}}`, до 8 устройств |
| POST | `/push/unsubscribe` | `endpoint`, удаление своей подписки |
| POST | `/push/test` | Тест подписанным устройствам владельца |

## Ошибки

Формат — `{error:"Понятное сообщение"}`. Статусы: 400 — неверные поля/код; 401 — нет действующей сессии; 403 — запрещённый origin или запрещённая операция; 404 — нет своей сущности/маршрута; 409 — занятый логин; 413 — размер; 415 — тип тела; 429 — лимит; 500 — внутренняя ошибка; 502/503 — недоступный внешний сервис или компонент.

Чужой питомец возвращает 404. Тела запросов, коды, токены и медицинские тексты не записываются в HTTP-лог. Внешним сервисам нужны настройки и интернет, фактическое подключение проверяется отдельно. Архитектура — [architecture.md](architecture.md), публикация — [deploy.md](deploy.md).
