# Telegram в полном приложении

Код находится в `backend/telegram_runtime.py`; запуск и отправка — в `backend/server.py`. Это часть серверного приложения, не отдельный frontend.

Нужны собственный бот, `TELEGRAM_BOT_TOKEN` в приватной конфигурации и работающий Python-сервер с доступом к Telegram. Pages-демо не запускает бота и не использует прежнего бота команды.

Пользователь создаёт аккаунт на сайте, в настройках получает одноразовую ссылку и нажимает Start. Сервер проверяет start-код и связывает chat_id с аккаунтом. Пароль не отправляется в чат. `/start` без кода показывает меню со входом через сайт и отдельным серверным демо; `/pets` показывает питомцев, `/upcoming` — ближайшие дела, `/disconnect` разрывает связь. Свободный вопрос обрабатывается через поиск по записям.

Long polling получает обновления через getUpdates. Один активный polling-процесс обязателен. Отдельный worker проверяет напоминания и события публичных меток. `public_tags.notify` выбирает ещё не отправленные события, вызывает sendMessage и помечает успешную доставку. Ошибки приводят к повторным попыткам с задержкой; успешное сохранение отчёта в SQLite ещё не означает доставку в Telegram.

Токен храните только на сервере. Старые токены, адреса хакатонной VM и chat_id не нужны для запуска собственной копии.
